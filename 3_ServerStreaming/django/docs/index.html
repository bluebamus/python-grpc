3_ServerStreaming — Django HTTP→gRPC 게이트웨이 Django

gRPC 서버 스트리밍(요청 1 → 응답 다수)을 HTTP 스트리밍(SSE)으로 중계하는 실무 가이드

1. 개요 — 실무에서 어디에 쓰나

Django 로 운영 중인 웹/관리자 서비스가 내부 gRPC 마이크로서비스의 서버 스트리밍 API 를 호출하는 상황은 흔합니다. 진행률 표시, 실시간 알림, 로그 tailing, LLM 토큰 스트리밍처럼 하나의 요청에 결과가 여러 조각으로 도착하는 흐름이 그렇습니다.

브라우저는 gRPC 스트림을 직접 받기 어렵기 때문에, Django 뷰가 게이트웨이가 되어 gRPC 서버 스트림을 받아 StreamingHttpResponse 로 SSE 청크를 흘려보냅니다. 응답을 모아서 한 번에 주지 않는다는 점이 핵심입니다.

요청은 1개지만 응답은 서버가 yield 하는 만큼 stream 으로 돌아옵니다. 뷰의 제너레이터가 이 스트림을 순회하며 메시지마다 data: {json}\n\n SSE 청크를 yield 합니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 POST /chat-stream {"message":"시작"} 호출
  2. Django 뷰가 JSON 파싱·검증 (빈 문자열 → 422)
  3. get_client() 로 재사용 중인 스텁의 ChatStream 호출 → iterator 획득
  4. 첫 메시지를 미리 한 번 당겨(peek) 본다 — 백엔드 UNAVAILABLE 이면 헤더가 나가기 전이라 503 매핑 가능
  5. StreamingHttpResponse 가 제너레이터를 돌며 메시지마다 SSE 청크를 흘려보내고, 끝나면 event: done 으로 마무리

4. 코드 핵심 포인트

서버 스트림 순회 (gateway/grpc_client.py)

def chat_stream(self, message, timeout=None):
    request = message_pb2.ChatMessage(message=message)
    call = self._stub.ChatStream(request, timeout=timeout)
    for response in call:        # 응답이 도착하는 대로
        yield response.message   # 제너레이터로 흘려보냄

SSE 로 중계 (gateway/views.py)

def event_generator():
    for msg in stream:
        yield f"data: {json.dumps({'message': msg})}\n\n"
    yield "event: done\ndata: {...}\n\n"

return StreamingHttpResponse(event_generator(), content_type="text/event-stream")

5. 실무 적용 시 고려사항

WSGI 는 스트리밍에 한계가 있습니다. Django 동기 뷰 + WSGI 에서 StreamingHttpResponse 는 동작하지만, 워커 스레드가 스트림이 끝날 때까지 묶입니다. 장시간 스트림이 많다면 ASGI(async 뷰)나 별도 스트리밍 게이트웨이를 고려하세요.
  • 버퍼링 주의: 본 샘플은 X-Accel-Buffering: no, Cache-Control: no-cache 헤더로 프록시 버퍼링을 막습니다. 그래도 GZipMiddleware 등은 스트림을 모아버릴 수 있으니 함께 점검하세요.
  • 스트림 시작 후 상태코드 고정: 첫 청크를 보내면 200 이 확정됩니다. 도중 실패는 본문 error 이벤트로만 알릴 수 있습니다.
  • 연결 종료 전파: 클라이언트가 끊기면 gRPC 호출도 취소해 백엔드 자원을 낭비하지 않도록 하세요.
  • 채널과 fork: gunicorn prefork 시 채널은 워커 안에서 만들어야 합니다. 지연 생성(get_client)이 이를 만족합니다.
  • 하트비트: 메시지 간격이 길면 주기적 코멘트(: ping\n\n)로 유휴 연결 종료를 방지하세요.

6. 실행 · 테스트

uv sync

# 백엔드 gRPC 서버 (상위 폴더 예제, 포트 50053)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run python manage.py runserver

# SSE 스트림 수신 (-N 으로 버퍼 끄기)
curl -N -X POST localhost:8000/chat-stream \
  -H "content-type: application/json" -d '{"message":"시작"}'

# 통합 테스트
uv run pytest

통합 테스트는 서버가 정확히 N개(예: 3개)를 stream 으로 보낼 때 게이트웨이를 통해 클라이언트가 streaming_content 로 N개를 순서대로 모두 수신하는지, 백엔드 부재 시 503 으로 매핑되는지를 결정론적으로 검증합니다.
