16_TLS보안 — Django HTTP→gRPC 게이트웨이 Django

게이트웨이와 백엔드 사이 통신을 TLS 로 암호화·인증하는 실무 가이드

1. 개요 — 실무에서 어디에 쓰나

마이크로서비스 사이의 트래픽도 신뢰할 수 없는 네트워크를 지납니다. 사내망이라도 도청(eavesdropping)·중간자 공격(MITM)·서비스 사칭을 막으려면 서비스 간 통신을 TLS 로 암호화하고 서버 신원을 인증해야 합니다.

이 샘플은 HTTP→gRPC 게이트웨이가 외부에는 REST 를 노출하면서, 내부 gRPC 백엔드에는 grpc.secure_channel 로 연결합니다. 평문 insecure_channel 이 아니라, 서버 인증서를 검증한 뒤에만 RPC 가 흐릅니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 POST /hello {"name":"World"} 호출
  2. Django 뷰가 입력 검증 (빈 문자열 → 422)
  3. 게이트웨이가 루트 인증서(server.crt)로 만든 보안 채널의 스텁으로 SayHello 호출
  4. 첫 호출 시 TLS 핸드셰이크: 서버 인증서를 받아 루트로 검증하고, 호스트네임(SAN/CN)이 target 과 일치하는지 확인
  5. 검증 성공 시 암호화된 채널로 요청/응답 교환, 결과를 HTTP 로 반환

4. 코드 핵심 포인트

TLS 보안 채널 생성 (grpc_client.py)

with open(settings.GRPC_ROOT_CERT, "rb") as f:
    root_certificates = f.read()

credentials = grpc.ssl_channel_credentials(root_certificates=root_certificates)

options = []
if settings.GRPC_SSL_TARGET_NAME_OVERRIDE:   # 자체서명 CN 불일치 시
    options.append(("grpc.ssl_target_name_override",
                    settings.GRPC_SSL_TARGET_NAME_OVERRIDE))

channel = grpc.secure_channel(target, credentials, options=options)  # insecure 아님

자체서명 인증서와 호스트네임 검증

자체서명 인증서는 공인 CA 가 서명하지 않았으므로, 클라이언트가 그 인증서 자신을 루트(root) 로 신뢰하도록 root_certificates 에 넣어줍니다. 또한 인증서의 CN/SAN 과 접속 호스트가 달라 검증이 실패하면 grpc.ssl_target_name_override 로 검증 대상 이름을 인증서 값으로 바꿉니다. (이 샘플 인증서는 CN=localhost, SAN=localhost 라 localhost 접속 시 오버라이드가 필요 없습니다.)

5. 실무 적용 시 고려사항

인증서 관리가 핵심입니다. 인증서 경로·내용을 코드에 하드코딩하지 말고 설정/시크릿 매니저로 분리하고, 만료 전 갱신(rotation) 자동화를 반드시 갖추세요. 만료된 인증서는 서비스 전체 장애로 이어집니다.
  • 자체서명 vs 사설 CA: 데모는 자체서명으로 충분하지만, 실무에서는 사내 CA(혹은 cert-manager/Vault)로 발급해 신뢰 체인을 관리하세요.
  • mTLS(상호 인증): 더 강한 보안이 필요하면 서버뿐 아니라 클라이언트 인증서까지 검증하는 mTLS 를 적용합니다(ssl_server_credentials 의 require_client_auth=True + 클라이언트 call credentials).
  • 호스트네임 검증을 끄지 말 것: ssl_target_name_override 는 검증을 우회하는 게 아니라 '검증 대상 이름'만 바꾸는 것입니다. 인증서 SAN 을 올바로 발급하는 편이 정석이며, 검증 자체를 비활성화해선 안 됩니다.
  • 채널 재사용: TLS 핸드셰이크는 비쌉니다. 채널을 요청마다 만들지 말고 프로세스 수명 동안 재사용하세요(본 샘플은 모듈 레벨 get_client).
  • 관측성: 핸드셰이크 실패·인증서 만료 임박을 메트릭/알람으로 노출해야 "조용한 인증서 사고"를 예방할 수 있습니다.

6. 실행 · 테스트

# 의존성 설치
uv sync

# 백엔드 TLS gRPC 서버 (상위 폴더 예제, server.key/server.crt 사용)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run python manage.py runserver

# 통합 테스트 (TLS 서버를 직접 띄워 보안 채널 호출을 검증)
uv run pytest

통합 테스트는 add_secure_port 로 TLS gRPC 서버를 50066 에 띄우고, 게이트웨이가 secure_channel 로 호출해 Hello, World! 를 받는지 확인합니다. 또한 같은 포트에 평문 채널로 접속하면 거부되는 것을 확인해 insecure 가 아님을 분명히 증명합니다.
