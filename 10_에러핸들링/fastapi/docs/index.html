10_에러핸들링 — FastAPI HTTP→gRPC 게이트웨이 FastAPI

gRPC 상태코드를 HTTP 의미로 충실히 번역하는 게이트웨이를 실무 관점에서 구현하는 가이드

1. 개요 — 실무에서 어디에 쓰나

gRPC 백엔드는 실패를 풍부한 상태코드(StatusCode)로 표현합니다. 잘못된 입력은 INVALID_ARGUMENT, 권한 없음은 PERMISSION_DENIED, 일시 장애는 UNAVAILABLE 식입니다. 하지만 브라우저/모바일 같은 외부 클라이언트는 HTTP 상태코드로 말합니다. HTTP→gRPC 게이트웨이의 중요한 책임 중 하나가 바로 이 둘 사이의 에러 변환입니다.

이 예제의 Calculator.Divide 는 divisor=0 이면 INVALID_ARGUMENT 로 abort 합니다. 게이트웨이는 이를 400 Bad Request 로 매핑하고, 서버가 내려준 에러 상세(details)도 응답 본문에 담아 클라이언트가 원인을 정확히 알게 합니다.

정상 응답은 역방향으로 흐릅니다. 백엔드가 INVALID_ARGUMENT 등으로 abort 하면, 게이트웨이가 매핑 표에 따라 적절한 HTTP 상태코드(예: 400)와 에러 상세를 담아 클라이언트에 응답합니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 POST /divide {"dividend":10,"divisor":2} 호출
  2. FastAPI 가 Pydantic 으로 입력 검증 (숫자가 아니면 422)
  3. 게이트웨이가 재사용 중인 gRPC 스텁으로 Divide 호출
  4. 서버가 divisor=0 을 만나면 INVALID_ARGUMENT 로 abort
  5. 게이트웨이가 grpc.RpcError.code() 를 읽어 HTTP 상태코드로 매핑하고, details() 를 응답 본문에 포함

4. 코드 핵심 포인트

에러를 던지는 쪽 (server.py)

def Divide(self, request, context):
    if request.divisor == 0:
        context.abort(grpc.StatusCode.INVALID_ARGUMENT,
                      "Division by zero is not allowed.")
    return DivideResponse(quotient=request.dividend / request.divisor)

에러를 번역하는 쪽 (main.py)

try:
    quotient = client.divide(req.dividend, req.divisor)
except grpc.RpcError as exc:
    code = exc.code()
    http_status = _GRPC_TO_HTTP.get(code, 500)
    return JSONResponse(status_code=http_status, content={
        "error": {"grpc_status": code.name,
                  "http_status": http_status,
                  "detail": exc.details()}})

5. 실무 적용 시 고려사항

에러 상세를 그대로 노출하지 마세요. 내부 스택트레이스나 DB 오류 메시지가 details() 에 담겨 외부로 새면 정보 노출이 됩니다. 사용자에게 보여줄 메시지와 내부 로깅용 메시지를 구분하세요.
  • 매핑은 한 곳에서: gRPC→HTTP 매핑 표를 단일 위치(딕셔너리)로 관리해 엔드포인트마다 제각각이 되지 않게 합니다.
  • 기본값은 500: 표에 없는 상태코드는 안전하게 500 으로 떨어뜨리되, 원본 gRPC 코드를 로그에 남겨 원인 추적이 가능하게 합니다.
  • 입력 검증은 게이트웨이에서 먼저: 타입 오류 같은 명백한 문제는 Pydantic 으로 422 처리해 불필요한 gRPC 왕복을 줄입니다. 단, 도메인 규칙(0 으로 나누기 금지 등)은 권위 있는 서버가 판정하게 둡니다.
  • 리치 에러(google.rpc.Status): 필드 단위 오류 등 구조화된 상세가 필요하면 error_details 의 BadRequest/ErrorInfo 를 실어 보내고 게이트웨이에서 풀어주는 패턴을 고려하세요.
  • 관측성: 상태코드별 카운트를 메트릭으로 남기면 "조용한 4xx 급증"을 조기에 발견할 수 있습니다.

6. 실행 · 테스트

# 의존성 설치
uv sync

# 백엔드 gRPC 서버 (상위 폴더 예제, 포트 50060)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run uvicorn app.main:app --reload

# 통합 테스트 (결정론적 gRPC 서버를 직접 띄워 에러 매핑 검증)
uv run pytest

통합 테스트는 정상 나눗셈(200), divisor=0 → 400 (INVALID_ARGUMENT), 권한 거부 → 403 (PERMISSION_DENIED) 매핑을 결정론적으로 검증합니다.
