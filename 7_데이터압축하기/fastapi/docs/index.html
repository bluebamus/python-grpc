7_데이터압축하기 — FastAPI HTTP→gRPC 게이트웨이 FastAPI

큰 바이너리 응답을 gzip 압축 채널로 효율적으로 주고받는 게이트웨이 실무 가이드

1. 개요 — 실무에서 어디에 쓰나

이미지·썸네일, 직렬화된 ML 모델/피처, 대용량 JSON·로그 번들처럼 큰 바이너리(bytes)를 내부 gRPC 서비스에서 받아 외부로 중계해야 할 때가 많습니다. 이런 데이터를 압축 없이 그대로 전송하면 네트워크 대역폭과 지연이 늘어납니다. gRPC 채널/호출에 gzip 압축을 켜면, 반복성이 높은 데이터에서 전송 바이트가 크게 줄어듭니다. 압축/해제는 gRPC 런타임이 투명하게 처리합니다.

이 게이트웨이는 REST GET /data/{data_id} 를 노출하고, 내부에서 gzip 압축 채널로 DataService.GetData 를 호출합니다. 받은 bytes 는 JSON 으로 직접 실을 수 없으므로 base64 로 인코딩해 응답합니다.

응답은 역방향으로 흐릅니다. 서버가 bytes 를 반환하면 gzip 으로 압축돼 전송되고, 게이트웨이가 자동 해제한 뒤 base64 로 인코딩해 클라이언트에 응답합니다. 배정 포트는 50057 입니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 GET /data/1 호출
  2. 게이트웨이가 재사용 중인 gzip 압축 채널의 스텁으로 GetData(data_id="1") 호출
  3. 서버가 bytes 응답 → gRPC 가 gzip 으로 압축해 전송
  4. 게이트웨이가 압축 해제된 bytes 를 받아 base64 인코딩
  5. {"data_id","data_base64","size","elapsed_ms"} JSON 으로 응답. 없는 id 면 NOT_FOUND → 404

4. 코드 핵심 포인트

압축 채널 생성 (grpc_client.py)

channel = grpc.insecure_channel(
    target, compression=grpc.Compression.Gzip)
stub = example_pb2_grpc.DataServiceStub(channel)

# 호출 시에도 명시 가능 (채널 기본값을 덮어씀)
response = stub.GetData(
    request, compression=grpc.Compression.Gzip)

bytes → base64 직렬화 (main.py)

data = client.get_data(data_id)          # bytes
return DataResponse(
    data_id=data_id,
    data_base64=base64.b64encode(data).decode("ascii"),
    size=len(data),
    elapsed_ms=...,
)

5. 실무 적용 시 고려사항

압축이 항상 이득은 아닙니다. 이미 압축된 데이터(JPEG, PNG, mp4, zip)나 아주 작은 메시지는 gzip 으로 다시 압축해도 효과가 거의 없고, CPU 만 더 씁니다. 페이로드 특성에 따라 압축 적용 여부를 선택하세요.
  • CPU vs 대역폭 트레이드오프: 압축은 CPU 를 쓰는 대신 네트워크를 아낍니다. 내부망(빠른 네트워크) + 높은 QPS 환경에서는 압축이 오히려 CPU 병목을 만들 수 있으니 벤치마크로 결정하세요.
  • 채널 vs 호출 단위: insecure_channel(compression=...) 로 채널 전체에 걸거나, stub.GetData(req, compression=...) 로 호출마다 다르게 줄 수 있습니다. 호출 단위가 더 세밀합니다.
  • 서버도 압축을 지원해야: 클라이언트가 압축을 요청해도 서버가 해당 알고리즘을 알아야 응답이 압축됩니다(본 샘플은 서버도 Gzip 설정).
  • bytes 직렬화: JSON 에는 raw bytes 를 실을 수 없습니다. base64 는 약 33% 크기 증가가 있으므로, 정말 큰 바이너리는 별도 다운로드 엔드포인트 (octet-stream)로 스트리밍하는 편이 나을 수 있습니다.
  • 관측성: 압축 전/후 크기와 지연을 로깅해 효과를 추적하세요. 본 샘플은 size 와 elapsed_ms 를 응답에 포함합니다.

6. 실행 · 테스트

# 의존성 설치
uv sync

# 백엔드 gRPC 서버 (상위 폴더 예제, 포트 50057)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run uvicorn app.main:app --reload

# 통합 테스트 (gRPC 서버를 직접 띄워 압축 호출/디코딩 검증)
uv run pytest

통합 테스트는 서버가 b"X" * 10000 을 반환하게 하고, 게이트웨이가 gzip 압축 채널로 받아 base64 디코딩 후 size == 10000 인지, 없는 id 는 404 인지 결정론적으로 검증합니다.
