7_데이터압축하기 — Django HTTP→gRPC 게이트웨이 Django

큰 바이너리 응답을 gzip 압축 채널로 효율적으로 주고받는 게이트웨이 실무 가이드

1. 개요 — 실무에서 어디에 쓰나

Django 로 운영하는 웹/관리자 서비스가 내부 gRPC 마이크로서비스에서 큰 바이너리(이미지, 직렬화된 모델, 대용량 리포트 등 bytes)를 받아 중계하는 상황은 흔합니다. 압축 없이 그대로 전송하면 대역폭과 지연이 늘어납니다. gRPC 채널에 gzip 압축을 적용하면 반복성 높은 데이터의 전송량을 크게 줄일 수 있고, 압축/해제는 gRPC 가 투명하게 처리합니다.

이 게이트웨이는 REST GET /data/{data_id} 를 노출하고, 내부에서 gzip 압축 채널로 DataService.GetData 를 호출한 뒤, 받은 bytes 를 base64 로 인코딩해 JSON 으로 응답합니다.

채널/스텁은 get_client() 로 프로세스 단위 재사용됩니다. 서버가 반환한 bytes 는 gzip 으로 압축돼 전송되고, 뷰가 자동 해제 후 base64 로 인코딩해 응답합니다. 배정 포트는 50057 입니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 GET /data/1 호출
  2. get_client() 로 재사용 중인 gzip 압축 채널 스텁의 GetData(data_id="1") 호출
  3. 서버가 bytes 반환 → gRPC 가 gzip 으로 압축해 전송
  4. 뷰가 압축 해제된 bytes 를 받아 base64 인코딩
  5. {"data_id","data_base64","size","elapsed_ms"} 응답. 없는 id 는 NOT_FOUND → 404

4. 코드 핵심 포인트

압축 채널 생성 (gateway/grpc_client.py)

channel = grpc.insecure_channel(
    settings.GRPC_TARGET,
    compression=grpc.Compression.Gzip)
stub = example_pb2_grpc.DataServiceStub(channel)

# 호출 단위로도 지정 가능
response = stub.GetData(
    request, compression=grpc.Compression.Gzip)

채널 재사용 (gateway/grpc_client.py)

def get_client() -> GrpcClient:
    global _client
    if _client is None:
        _client = GrpcClient()   # 압축 채널 1회 생성 후 재사용
    return _client

5. 실무 적용 시 고려사항

압축이 항상 이득은 아닙니다. 이미 압축된 데이터(JPEG, PNG, mp4, zip)나 아주 작은 메시지는 gzip 재압축 효과가 거의 없고 CPU 만 더 씁니다. 페이로드 특성에 맞춰 적용 여부를 선택하세요.
  • WSGI 동기 모델: Django 동기 뷰의 gRPC 호출은 요청 스레드를 블로킹합니다. 큰 데이터의 압축/해제는 CPU 를 쓰므로 워커 수·타임아웃을 함께 설계하세요.
  • 채널과 fork: gunicorn prefork 시 채널은 fork 이후(워커 안)에서 만들어야 합니다. 본 샘플의 지연 생성(get_client)이 이를 만족합니다.
  • 채널 vs 호출 단위 압축: 채널 전체에 걸거나 호출마다 다르게 줄 수 있습니다. 호출 단위가 더 세밀합니다.
  • 서버도 압축 지원 필요: 클라이언트가 압축을 요청해도 서버가 해당 알고리즘을 알아야 응답이 압축됩니다(본 샘플은 서버도 Gzip).
  • bytes 직렬화: JSON 엔 raw bytes 를 실을 수 없어 base64 로 인코딩합니다(약 33% 증가). 정말 큰 바이너리는 별도 스트리밍 다운로드가 나을 수 있습니다.

6. 실행 · 테스트

uv sync

# 백엔드 gRPC 서버 (상위 폴더 예제, 포트 50057)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run python manage.py runserver

# 통합 테스트
uv run pytest

통합 테스트는 서버가 b"X" * 10000 을 반환하게 하고, 게이트웨이가 gzip 압축 채널로 받아 base64 디코딩 후 size == 10000 인지, 없는 id 는 404 인지 결정론적으로 검증합니다.
