8_데이터압축기법 — Django HTTP→gRPC 게이트웨이 Django

채널 기본 압축과 호출 단위 압축 오버라이드를 실무 관점에서 구현·운영하는 가이드

1. 개요 — 실무에서 어디에 쓰나

Django 로 운영 중인 웹/관리자 서비스가 내부 gRPC 마이크로서비스에서 대용량 데이터(바이너리 번들, 대형 리포트 등)를 가져오는 상황은 흔합니다. 이때 전송 압축으로 대역폭과 지연을 줄일 수 있습니다. 다만 압축은 CPU 비용을 동반하므로, 네트워크 환경·페이로드 크기에 따라 알고리즘을 선택할 수 있어야 합니다.

이 샘플은 (1) 채널 단위 기본 압축과 (2) 호출 단위 오버라이드를 모두 보여주며, 알고리즘(None/Deflate/Gzip)을 settings 또는 쿼리스트링으로 선택합니다.

채널/스텁은 get_client() 로 프로세스 단위 재사용됩니다. 응답의 bytes 는 base64 로 인코딩해 JSON 으로 반환합니다. 압축은 전송 계층에서 일어나므로 복원된 데이터(size)는 알고리즘과 무관하게 동일합니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 GET /data/1?compression=gzip 호출
  2. Django 뷰가 compression 쿼리값을 검증 (알 수 없는 값 → 400)
  3. get_client() 로 재사용 중인 스텁의 GetData 호출 — compression= 인자로 채널 기본값을 호출 단위로 오버라이드
  4. gRPC 런타임이 요청/응답을 해당 알고리즘으로 압축·복원
  5. 복원된 bytes 를 base64 로 인코딩해 {data_id, data_base64, size, compression, elapsed_ms} 로 응답

4. 코드 핵심 포인트

설정 분리 (config/settings.py)

GRPC_TARGET = os.environ.get("GRPC_TARGET", "localhost:50058")
GRPC_DEFAULT_COMPRESSION = os.environ.get("GRPC_DEFAULT_COMPRESSION", "gzip")

채널 기본 압축 + 호출 오버라이드 (gateway/grpc_client.py)

default = grpc.Compression.Gzip       # settings 에서 선택
channel = grpc.insecure_channel(target, compression=default)
# ... 호출 단위 오버라이드
kwargs = {"timeout": 5.0}
if compression is not None:
    kwargs["compression"] = grpc.Compression.Deflate
stub.GetData(request, **kwargs)

5. 실무 적용 시 고려사항

압축은 공짜가 아닙니다. CPU 시간과 대역폭의 트레이드오프입니다. 빠른 내부망에서는 압축이 오히려 지연을 늘릴 수 있고, 모바일/WAN 에서는 큰 이득입니다. 페이로드 크기·네트워크 환경에 따라 알고리즘을 선택하세요.
  • 작은 메시지엔 무압축: 수백 바이트 메시지는 압축 헤더 오버헤드가 이득보다 큽니다. 큰 페이로드에만 압축을 켜세요.
  • 이미 압축된 데이터: JPEG/MP4 등은 재압축 이득이 거의 없고 CPU 만 낭비합니다(none 권장).
  • WSGI 동기 모델: 동기 뷰에서 gRPC 압축 호출은 요청 스레드를 점유합니다. 대용량·고압축은 CPU 를 더 쓰므로 워커 수·타임아웃을 함께 설계하세요.
  • 채널과 fork: gunicorn prefork 시 채널은 fork 이후(워커 안)에서 만들어야 합니다. 본 샘플의 지연 생성(get_client)이 이를 만족합니다.
  • 관측성: 압축률·CPU·지연을 메트릭으로 남기세요. 본 샘플은 elapsed_ms 와 size 를 응답에 포함합니다.

6. 실행 · 테스트

uv sync

# 게이트웨이 기동
uv run python manage.py runserver

# 호출 (압축 알고리즘 선택)
curl "localhost:8000/data/1?compression=gzip"
curl "localhost:8000/data/1?compression=none"

# 통합 테스트 (gRPC 서버를 직접 띄워 압축 호출 검증, 포트 50058)
uv run pytest

통합 테스트는 gzip·none·deflate 압축 호출이 모두 성공하고, 알고리즘과 무관하게 복원된 데이터 size 가 동일함을 결정론적으로 검증합니다.
