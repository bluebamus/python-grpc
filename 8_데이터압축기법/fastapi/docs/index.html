8_데이터압축기법 — FastAPI HTTP→gRPC 게이트웨이 FastAPI

채널 기본 압축과 호출 단위 압축 오버라이드를 실무 관점에서 구현·운영하는 가이드

1. 개요 — 실무에서 어디에 쓰나

gRPC 는 큰 페이로드(이미지 메타, 로그 번들, 대용량 JSON·바이너리)를 주고받을 때 전송 압축으로 대역폭과 지연을 크게 줄일 수 있습니다. 데이터센터 내부처럼 네트워크가 빠르면 압축의 CPU 비용이 더 클 수도 있고, 모바일·WAN 처럼 대역폭이 비싸면 압축이 큰 이득입니다. 따라서 압축 알고리즘을 환경에 맞게 선택할 수 있어야 합니다.

이 샘플은 두 가지 적용 지점을 보여줍니다. (1) 채널 단위 기본 압축: 채널을 만들 때 한 번 지정하면 모든 호출에 적용됩니다. (2) 호출 단위 오버라이드: 특정 호출만 다른 알고리즘(또는 무압축)으로 보낼 수 있습니다.

응답의 bytes 는 JSON 으로 직접 실을 수 없으므로 게이트웨이가 base64 로 인코딩해 반환합니다. 압축은 전송 계층에서 일어나므로 복원된 바이트(그리고 size)는 알고리즘과 무관하게 동일합니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 GET /data/1?compression=gzip 호출
  2. FastAPI 가 compression 쿼리값을 검증 (알 수 없는 값 → 400)
  3. 게이트웨이가 재사용 중인 gRPC 스텁의 GetData 를 호출 — 이때 compression= 인자로 채널 기본값을 호출 단위로 오버라이드
  4. gRPC 런타임이 요청/응답을 해당 알고리즘으로 압축·복원
  5. 게이트웨이가 복원된 bytes 를 base64 로 인코딩해 {data_id, data_base64, size, compression, elapsed_ms} 로 응답

4. 코드 핵심 포인트

채널 기본 압축 (grpc_client.py)

default = grpc.Compression.Gzip            # 설정에서 선택
channel = grpc.insecure_channel(target, compression=default)
stub = DataServiceStub(channel)

호출 단위 오버라이드 (grpc_client.py)

kwargs = {"timeout": 5.0}
if compression is not None:                # 호출마다 다르게 지정 가능
    kwargs["compression"] = grpc.Compression.Deflate
stub.GetData(request, **kwargs)

5. 실무 적용 시 고려사항

압축은 공짜가 아닙니다. CPU 시간과 대역폭의 트레이드오프입니다. 데이터센터 내부(빠른 망)에서는 압축이 오히려 지연을 늘릴 수 있고, 모바일/WAN 에서는 큰 이득입니다. 페이로드 크기·네트워크 환경에 따라 알고리즘을 선택하세요.
  • 작은 메시지엔 무압축: 수백 바이트 메시지는 압축 헤더 오버헤드가 이득보다 큽니다. 큰 페이로드에만 압축을 켜는 것이 유리할 때가 많습니다.
  • 이미 압축된 데이터: JPEG/PNG/MP4 같은 데이터는 재압축 이득이 거의 없고 CPU 만 낭비합니다(none 권장).
  • 채널 기본 vs 호출 단위: 대부분 채널 기본으로 충분하지만, 특정 대용량 호출만 압축하고 싶다면 호출 단위 오버라이드가 유연합니다.
  • 서버 측 협상: 서버는 클라이언트가 보낸 인코딩을 자동 해석하고, 응답도 클라이언트가 수용 가능한 알고리즘으로 보냅니다. 양쪽이 같은 알고리즘을 지원해야 압축이 실제로 적용됩니다.
  • 관측성: 압축률·CPU·지연을 메트릭으로 남겨 알고리즘 선택을 데이터로 검증하세요. 본 샘플은 elapsed_ms 와 size 를 응답에 포함합니다.
  • 채널 재사용: 채널 생성은 비쌉니다. 앱 수명 동안 재사용하세요 (본 샘플은 lifespan 에서 1회 생성).

6. 실행 · 테스트

# 의존성 설치
uv sync

# 게이트웨이 기동
uv run uvicorn app.main:app --reload

# 호출 (압축 알고리즘 선택)
curl "localhost:8000/data/1?compression=gzip"
curl "localhost:8000/data/1?compression=none"

# 통합 테스트 (gRPC 서버를 직접 띄워 압축 호출 검증, 포트 50058)
uv run pytest

통합 테스트는 gzip·none·deflate 압축 호출이 모두 성공하고, 알고리즘과 무관하게 복원된 데이터 size 가 동일함을 결정론적으로 검증합니다.
