12_서버 리플렉션 — Django HTTP→gRPC 게이트웨이 Django

클라이언트가 .proto 없이도 서버에 직접 물어 서비스를 발견하는 게이트웨이 가이드

1. 개요 — 실무에서 어디에 쓰나

서버 리플렉션(Server Reflection)은 gRPC 서버가 자신이 노출하는 서비스/메서드/메시지 스키마를 런타임에 알려주는 표준 서비스입니다. 클라이언트가 미리 컴파일된 .proto 를 갖고 있지 않아도, 서버에 직접 물어 "어떤 서비스가 있는지"를 동적으로 알아낼 수 있습니다.

실무에서는 grpcurl 같은 디버깅 도구, API 게이트웨이의 동적 라우팅, 서비스 디스커버리/카탈로그, 개발용 탐색 UI 등에서 활용됩니다. 이 샘플은 게이트웨이가 REST GET /services 요청을 받으면 내부적으로 리플렉션을 호출해 서비스 목록을 JSON 으로 돌려줍니다.

2. 아키텍처 / 흐름도

브라우저 / 클라이언트
REST(JSON)
→
Django 게이트웨이
GET /services · POST /echo
→
gRPC 채널
Echo + Reflection 스텁
→
gRPC 서버
EchoService + 리플렉션 ON

/echo 는 평범한 unary 비즈니스 호출이고, /services 는 ServerReflectionInfo 양방향 스트리밍 RPC 로 서비스 목록을 받아옵니다.

3. 호출 흐름 (단계별)

  1. 클라이언트가 GET /services 호출
  2. 게이트웨이가 ServerReflectionStub 으로 ServerReflectionRequest(list_services="*") 전송
  3. 서버가 노출 서비스 목록을 응답 스트림으로 반환
  4. 게이트웨이가 list_services_response.service[].name 을 파싱
  5. {"services": ["reflection_example.EchoService", ...]} 로 응답

4. 코드 핵심 포인트

서버 측 — 리플렉션 활성화 (server.py / conftest.py)

from grpc_reflection.v1alpha import reflection

SERVICE_NAMES = (
    reflection_example_pb2.DESCRIPTOR
        .services_by_name["EchoService"].full_name,  # reflection_example.EchoService
    reflection.SERVICE_NAME,                           # 리플렉션 서비스 자신
)
reflection.enable_server_reflection(SERVICE_NAMES, server)

클라이언트 측 — 서비스 목록 조회 (grpc_client.py)

from grpc_reflection.v1alpha import reflection_pb2, reflection_pb2_grpc

stub = reflection_pb2_grpc.ServerReflectionStub(channel)
req = reflection_pb2.ServerReflectionRequest(list_services="*")
for resp in stub.ServerReflectionInfo(iter([req])):
    for svc in resp.list_services_response.service:
        names.append(svc.name)   # "reflection_example.EchoService"

5. 실무 적용 시 고려사항

보안이 가장 중요합니다. 리플렉션은 서버의 전체 API 스키마를 노출하므로, 공개 인터넷에 무방비로 켜두면 공격 표면이 됩니다. 운영 환경에서는 내부망/사설 게이트웨이 뒤에서만 켜거나, 인증된 요청에만 허용하는 것이 안전합니다.
  • UNIMPLEMENTED 처리: 리플렉션을 끈 서버에 /services 를 호출하면 UNIMPLEMENTED 가 옵니다. 게이트웨이는 이를 501 로 매핑해 "이 기능 미지원"임을 명확히 합니다.
  • 스트리밍 RPC: 리플렉션은 양방향 스트리밍입니다. 단일 요청이라도 이터레이터로 감싸 보내고, 응답도 스트림으로 받습니다.
  • 버전: 패키지는 v1alpha 와 v1 이 있습니다. 도구/서버 호환을 위해 보통 v1alpha 를 함께 켜둡니다.
  • 채널 재사용: 채널 생성은 비쌉니다. Echo 스텁과 리플렉션 스텁은 같은 채널을 공유합니다(본 샘플은 모듈 레벨에서 1회 생성).
  • 스키마 캐싱: 매 요청마다 리플렉션을 치면 부하가 됩니다. 서비스 목록/디스크립터는 캐시하고 주기적으로만 갱신하는 것이 좋습니다.

6. 실행 · 테스트

# 의존성 설치 (grpcio-reflection 포함)
uv sync

# 백엔드 gRPC 서버 (상위 폴더 예제, 포트 50062)
cd .. && uv run python server.py

# 게이트웨이 기동
uv run python manage.py runserver

# 통합 테스트 (리플렉션 켠 서버를 직접 띄워 검증)
uv run pytest

통합 테스트는 리플렉션을 켠 서버를 띄워 /services 응답에 reflection_example.EchoService 가 포함되는지(리플렉션으로 서비스가 발견되는지)를 검증합니다.
